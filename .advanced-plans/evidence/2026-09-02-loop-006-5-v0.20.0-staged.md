Taken by machine rather than by eye: extract the section between the `[0.20.0]` and

## Check 4 rests on a false premise, and the premise is the finding

Check 4 reads: *"each entry names the loop it came from, **as the CHANGELOG's existing
sections do**"*.

They do not. Measured on the file as committed:

```
loop-NNN mentions inside the 0.20.0 section : 9
loop-NNN mentions in the rest of CHANGELOG  : 0
sections in the rest                        : 15
```

Fifteen prior sections, zero loop references. The clause describes a convention the
CHANGELOG has never had — another check whose subject is a string the plan typed rather
than a fact read off the machine, which is this phase's whole subject matter.

The requirement itself is good and was satisfied: every 0.20.0 entry names its loop, and
`[0.20.0]` is now the only section in the file that does. Recorded rather than silently
inherited, because a later reader following the "existing sections" would find nothing to
follow.

## markdownlint caught defects in this loop's own prose, twice

The gate that was vacuous until 2026-08-31 is now load-bearing, and it proved it on the
author of this record rather than on anyone else.

```
run 1  rc=1   10 MD049 errors, all inside the [0.20.0] section just written
run 2  rc=0   Summary: 0 issues in 0 files
run 3  rc=1    2 MD049 errors, both in the release-checklist prose just written
run 4  rc=0   Summary: 0 issues in 0 files  (95 files linted)
```

Both failures were the same rule and the same habit: asterisk emphasis where
`.markdownlint-cli2.jsonc` wants underscore. Neither reached a commit. Run it **bare** —
the globs and the rules both live in the config, so a bare run is exactly what CI runs, and
passing `--config` is how this gate became vacuous in the first place.

## A pipe in the collection path, disclosed

The CI-equivalent suite was run as a background command ending `… | tail -15`, and the
harness therefore reported *"exit code 0"* for **`tail`**, not for pytest. That is F25, in
the same session that wrote the checklist's warning about it.

The result stands on the summary line rather than on that exit code: `1014 passed, 1
skipped in 470.21s`, with no `failed` and no `error` token in the output. A pytest summary
naming zero failures is direct evidence; the exit code beside it was not. The checklist now
records both the figure and the trap, naming this run as the instance.
