## Headless Results

### REG-7 Static Analysis — Hook Scope Validation

**Source file analysed:** `references/settings-snippet.json` (loop-001 output)

**Matcher description:** `PostToolUse` hook with `matcher: "Write"`. After every Write tool call, a Node.js one-liner checks `CLAUDE_TOOL_INPUT_PATH`. It fires a console suggestion only if:
1. The path starts with `os.homedir() + '/.gstack/projects/'` (the prefix guard)
2. The basename matches `/-design-\d/` (the filename-pattern guard)

Both guards must pass for any output to appear. Any write that fails either guard causes the script to exit 0 silently — no interference with normal development.

| Sub-case | Input path | Verdict | Evidence / matcher field |
|---|---|---|---|
| (a) Hook SHOULD fire — design doc under ~/.gstack/projects/ | `~/.gstack/projects/MungoHarvey-Advanced-AI-Workflows/mharvey2-main-design-20260522-120000.md` | PASS | Guard 1: `p.startsWith(h + '/.gstack/projects/')` = true. Guard 2: `/-design-\d/.test('mharvey2-main-design-20260522-120000.md')` = true (matches `-design-2`). Console log fires with suggestion. |
| (b) Hook should NOT fire — path outside ~/.gstack/projects/ | `~/Documents/random/file.md` | PASS | Guard 1: `p.startsWith(h + '/.gstack/projects/')` = false. Script falls through. Exit 0 silently. Correct rejection. |
| (c) Hook should NOT fire — under ~/.gstack/projects/ but wrong filename pattern | `~/.gstack/projects/SomeProject/learnings.jsonl` | PASS | Guard 1 passes (path is under prefix). Guard 2: `/-design-\d/.test('learnings.jsonl')` = false. Script falls through. Exit 0 silently. Correct rejection — the filename pattern guard prevents spurious fires on non-design-doc writes. |
| (d) Idempotency — back-to-back writes to same design doc | Two sequential Write calls to the same `~/.gstack/projects/…-design-….md` path | PASS (with explanation) | The `PostToolUse` hook fires once per Write tool invocation — not twice per write. Two sequential Write calls produce two hook messages, which is expected PostToolUse semantics. Idempotency of `/gstack-to-plans` itself is guaranteed by gstack-to-plans SKILL.md Step 3: if destination content is identical to source, the skill exits as a no-op. `_merge_instructions.debounce_note` in settings-snippet.json explicitly documents this design decision. |

**REG-7 Overall Verdict: PASS**

The hook scope is correctly restricted. The two-guard design (prefix check + filename-pattern check) means:
- Writes inside `~/.gstack/projects/` to non-design-doc files do not trigger the suggestion
- Writes anywhere else are completely silent
- The hook cannot interfere with normal development workflows

**Windows note (from `_merge_instructions.windows_note`):** `os.homedir()` is cross-platform; on Windows it resolves to `%USERPROFILE%` correctly. No Windows-specific path issue found.
